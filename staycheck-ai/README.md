# StayCheck AI(宿泊施設向け 清掃写真チェック支援)

AIが清掃写真を一次チェックし、確認作業を支援します。

清掃後の写真をまとめて取り込むと、AI(OpenAI API)が1枚ずつ
「◎ 良好 / ○ 基準内 / ◇ 確認推奨 / △ 要調整」の4段階で判定し、問題のありそうな写真から順に表示する
Webアプリです。AIの判定は一次チェックであり、最終的な判断は利用者が行います。

> **審査員の方へ**
> 実際の操作の様子は、提出した操作動画でご覧いただけます。このリポジトリはそのソースコードです。
> ローカルで動かす場合は、ご自身のOpenAI APIキーが必要で、判定した枚数に応じて料金がかかります
> (「[API利用時の従量課金に関する注意事項](#api利用時の従量課金に関する注意事項)」を参照)。
> 現在のバージョン: v0.4.3.1(開発・検証中の試作品)

## 開発背景と解決したい課題

民泊の清掃では、清掃が終わるたびにスタッフが部屋の写真を撮り、管理者がその写真を1枚ずつ目で確認しています。
物件が増えるほど写真は増え、見落としを防ぐための確認に時間がかかります。

StayCheck AIは、この確認作業をAIの一次チェックで支援します。AIが答えを決めるのではなく、
**人が確認すべき写真を絞り込み、優先順位をつける**ための道具です。

- AIが断定できない写真は「◇ 確認推奨」として人の確認に回し、明らかな問題だけを「△ 要調整」にする
- 管理者は、判定結果一覧の上(問題のありそうな写真)から順に確認すればよい

## 主な機能

- **写真の一括取り込み**: パソコンからまとめて追加(ドラッグ&ドロップ/クリック選択、最大300枚)。Google Driveのフォルダからの取り込みにも対応(任意機能)
- **AIによる4段階の判定**: 6枚ずつ並列で判定し、API側の混雑(429)で失敗した場合は時間をおいて自動で再試行
- **問題のありそうな順に表示**: 「△ 要調整」「◇ 確認推奨」が上位に並ぶ。写真を拡大すると、判定理由がチェック項目ごとに表示される
- **写真カテゴリ**: 玄関・ベッド・浴室・キッチンなどを指定すると、そのカテゴリに関係する項目だけを判定する
- **会社別・物件別のルール**: 物件管理画面で会社・物件ごとのルールを登録し、判定に反映できる(「標準基準 < 会社別 < 物件別」の順に優先)
- **判定履歴**: チェック作業ごとに結果を180日間保存し、会社・物件・期間で絞り込める(写真そのものは保存しない)
- **API利用コストの概算表示**: 判定ごとのトークン使用量と概算コストを表示
- **スマートフォン対応**: 360px幅の画面でも、メニュー・判定結果・拡大表示が使える
- **共有パスワードによるログイン**

### 判定ランク

| ランク | 意味 |
|---|---|
| ◎ 良好 | 問題なし |
| ○ 基準内 | 軽微な事項はあるが、AIが確信を持って「問題ない」と判断できる |
| ◇ 確認推奨 | AIが断定できない(反射・影・木目・模様・経年劣化・物件固有の設備など)。人の確認を促すランク |
| △ 要調整 | AIが明らかな異常と断定できる場合のみ(毛髪・ゴミ・残置物・ベッドの大きな乱れ・明らかな汚れ・破損など) |

## 使用技術

- Next.js 14(App Router)/ TypeScript / Tailwind CSS
- OpenAI API(gpt-5.5、Responses APIの画像入力で判定)
- Upstash Redis(会社・物件ルールと判定履歴の保存。任意)
- Google Drive API(OAuth 2.0、写真の取り込み。任意)
- テスト: Node.js標準のテストランナー(tsx経由)

## ローカル環境での起動方法

### 必要なもの

- Node.js 18.17以上(作者は Node.js 22 で確認)
- OpenAI APIキー(必須。[OpenAI Platform](https://platform.openai.com/api-keys) で発行)
- Upstash RedisのDB(任意。物件管理と判定履歴を使う場合に必要。[Upstash](https://upstash.com/) の無料プランで作れる)

### 手順

1. 依存パッケージをインストールする

   ```bash
   npm ci
   ```

2. 設定ファイルを作る。`.env.local.example` をコピーして `.env.local` という名前にする

   ```bash
   cp .env.local.example .env.local          # Mac / Linux
   Copy-Item .env.local.example .env.local   # Windows(PowerShell)
   ```

3. `.env.local` を開き、次の値を設定する

   | 変数 | 必須 | 内容 |
   |---|---|---|
   | `OPENAI_API_KEY` | 必須 | OpenAI APIキー |
   | `APP_PASSWORD` | 必須 | ログイン画面で入力するパスワード(自分で決める) |
   | `AUTH_SECRET` | 必須 | ログイン状態の署名に使う、長いランダムな文字列(例: `openssl rand -hex 32` で生成) |
   | `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | 任意 | 物件管理・判定履歴を使う場合 |
   | `GOOGLE_` で始まる4つ | 任意 | Google Driveからの取り込みを使う場合(下の「Google Drive連携」を参照) |

4. 起動する

   ```bash
   npm run build
   npm start
   ```

   開発用に起動する場合は、`npm run dev` でも動きます。

5. ブラウザで [http://localhost:3000](http://localhost:3000) を開き、`APP_PASSWORD` に設定したパスワードでログインする

Upstashを設定しない場合も、写真の判定はそのまま使えます(物件管理と履歴だけが使えなくなります)。

### 使い方

1. チェック画面で「物件名」を入力する(判定結果に付ける表示名)
2. 必要なら「物件固有ルール」で、物件管理に登録した会社・物件を選ぶ(未選択なら標準基準だけで判定)
3. 清掃後の写真を追加し、「判定開始」を押す
4. 判定結果一覧を上から確認する。行をクリックすると写真が拡大され、判定理由(チェック項目)が表示される

## API利用時の従量課金に関する注意事項

- **OpenAI APIは従量課金です。** 写真を1枚判定するたびに、使ったトークン数に応じた料金がかかります。
  料金は、APIキーを発行したOpenAIのアカウントに請求されます
- 作者の環境での実測例では、**1枚あたり約0.035ドル**でした(2枚の判定で0.0699ドル)。
  写真の内容・サイズ・カテゴリなどで変わるため、目安としてお考えください。
  この単価のままなら、300枚の判定で約10ドルになります
- 画面の「API利用コスト(概算)」は、`app/lib/pricing.ts` に書いた単価(gpt-5.5、入力 $5.00 / 出力 $30.00 per 1M tokens)から計算した**概算**です。
  実際の請求額は、OpenAIの管理画面で確認してください。単価は変更されることがあります([OpenAI API Pricing](https://openai.com/api/pricing/))
- 試すときは、少ない枚数から始めることをおすすめします。OpenAIの管理画面で、プロジェクトごとに利用額の上限
  (Spend limits)を設定しておくと安心です
- Upstash Redisは無料プランの範囲で動きます(データ量・コマンド数に上限あり。`docs/KNOWN_ISSUES.md` の KI-010)。
  Google Drive APIの利用に料金はかかりません

## データの扱いとセキュリティ

- 写真はブラウザのメモリ上だけで扱い、サーバーやDBには保存しません。判定のため、写真はOpenAI APIに送信されます
- 判定履歴として保存するのは、ファイル名・判定・要約・チェック項目などの結果だけです(180日で自動削除)
- APIキー・パスワードなどは `.env.local` に置き、リポジトリには含めません(`.gitignore` で除外)
- ログインは共有パスワード方式です。ログインした全員が同じ権限で、会社ごとのアクセス分離はありません
- 既知の課題(Next.js 14のサポート終了と残る脆弱性、ログイン失敗の回数制限の回避など)は
  [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md) にまとめています。インターネットに公開して運用する場合は、事前に確認してください
- 開発の記録は [docs/DEVELOPMENT_LOG.md](docs/DEVELOPMENT_LOG.md) にあります

## テスト

```bash
npm test                  # 単体テスト(ネットワーク不要)
npm run test:integration  # Redisを使う結合テスト(下記の環境変数が必要)
```

- 結合テストは `HISTORY_IT_REDIS_URL` / `HISTORY_IT_REDIS_TOKEN`(Upstash REST形式)が未設定なら、すべてスキップされます。
  localhost以外へ接続する場合は `HISTORY_IT_ALLOW_REMOTE=1` の指定が必要です
- 実行前にPCの時刻を同期してください。テストはRedisとの時計のずれを測って補正し、ずれが5分を超える場合はエラーで止まります
- テストは自分で作った履歴ID・キーだけを最後に削除します。「期限による実削除」のテストは、空の検証専用DBでのみ実行されます。
  本番のDBでは実行しないでください

v0.4.3.1では、単体テスト66件・結合テスト41件に加え、画面操作の自動検証79項目とスマートフォン表示の自動検証88項目
(いずれもAIの応答を模擬に置き換えて実施)の、計274項目がすべて合格しています。

## 技術的な補足

### ルール階層

判定ルールは `app/rules/` 配下で、標準基準・会社別ルール・物件別ルールの3階層として管理しています。

- 標準基準(`app/rules/standard/`): 会社に依存しない、一般的な宿泊施設向けの清掃チェック基準
- 会社別・物件別ルール: 物件管理画面から登録し、Upstash Redisに保存
- 各ルールは `id` 付きの構造化データで、`app/rules/resolveRules.ts` が「同じidがあれば物件→会社→標準の順で上書き」します。
  優先順位の判断をAIに任せない設計です。会社・物件を選ばない場合は標準基準だけで動作します

### 並列判定とレート制限への対応

- `app/(app)/page.tsx` の `CONCURRENCY_LIMIT`(6)で同時実行数を制御しています
- OpenAI APIのレート制限(429)が起きた場合、`app/lib/judgePhoto.ts` が指数バックオフ+ジッターで最大4回まで再試行します
  (`Retry-After` ヘッダーがあればそちらを優先)。それでも失敗した写真は「エラー」になり、「判定開始」を再度押すとその写真だけ再判定できます

### 判定履歴

- チェック作業1回を1件として、判定がすべて終わった後に保存します。保存に失敗しても判定結果には影響しません(画面に「再送」ボタンが出ます)
- 写真そのもの、プロンプト、OpenAIの応答、Cookie・IP・OAuthトークンなどは保存しません
- 仕組みの詳細は `app/lib/history/store.ts` と `app/lib/history/scripts.ts` の冒頭コメントを参照してください

### Google Drive連携(任意機能)

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、Google Drive APIを有効にする
2. 「認証情報」からOAuthクライアントID(ウェブアプリケーション)を作る
   - 承認済みのJavaScript生成元: `http://localhost:3000`
   - 承認済みのリダイレクトURI: `http://localhost:3000/api/google-drive/callback`
3. `.env.local` に `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` / `GOOGLE_DRIVE_FOLDER_ID` を設定する
   (フォルダIDは、Google Driveでフォルダを開いたときのURL末尾 `https://drive.google.com/drive/folders/【この部分】`)
4. チェック画面の「Google Driveから追加」タブで「Google Driveに接続」を押して認証する(初回のみ)

認証情報(トークン)はサーバー側にだけ保存し、ブラウザには渡しません
(Upstash Redisが設定されていればRedis、未設定の場合は開発時(`npm run dev`)に限り `.data/google-drive-tokens.json`。`.data/` は `.gitignore` で除外)。
対応する画像形式は JPEG・PNG・WebP です(HEICは非対応)。

### 主なファイル

- `app/(app)/page.tsx` — チェック画面(写真の追加・並列判定・結果一覧)
- `app/api/judge/route.ts` — OpenAI APIへの判定リクエスト
- `app/api/judge/categoryRules.ts` — 写真カテゴリごとの判定対象
- `app/lib/judgePhoto.ts` — 写真1枚の判定呼び出し(429時の再試行を含む)
- `app/lib/pricing.ts` — トークン単価とコスト計算
- `app/rules/` — 判定ルール(標準基準・ルールの統合・プロンプトの組み立て)
- `app/lib/history/` — 判定履歴の保存・取得
- `app/lib/auth.ts`、`middleware.ts` — 共有パスワード認証
